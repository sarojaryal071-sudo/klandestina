# Klandestina — Website

Plain HTML/CSS/JS site for Klandestina Cantina, Helsinki. No build step, no framework — open `index.html` in a browser (or serve the folder) and it runs.

## Editing the menu

Everything a dish needs — name, price, description, photo — lives in `data/menu.json`. Edit that file and the site updates automatically; no other file needs to change.

The full menu is split into `lunch`, `starters`, `tacos`, `chilaquiles`, `desserts`, `softDrinks`, `beer`, `cocktails`, `wine`, matching the real physical menu boards. `menu.categories` drives the tab row; most tabs map straight to one of those arrays, except `drinks`, which lists `groups: ["softDrinks","beer","cocktails","wine"]` and renders each as its own labeled sub-section in one panel (keeps the tab row to 6 pills instead of 9).

Per-item fields:
- `allergens`: raw letter codes as printed on the menu (`["M","G"]`, `["VEGAN"]`, etc.) — plain display text next to the name, not interactive. **The G/M/L legend itself needs confirming with the owner** — the menu photos show the letters but not what they stand for, so I've stored them as-is without guessing (G/M/L conventionally mean gluten/dairy/lactose-adjacent allergens on European menus, but I didn't want to assert that without the owner's key).
- `price`: usually a string (`"€15"`); `""` for items covered by a category-level price note instead (Lunch's fixed €14.90); or, for wine only, an object `{ glass12, glass16, glass24, bottle }` with `null` for sizes not offered — rendered as a fixed-width 4-column grid (12cl/16cl/24cl/Btl line up in the same columns on every wine row), still plain text.
- `image`: filename inside `images/dishes/`, only set on items that actually have a real dish photo. Omitting it isn't a gap to fill in later — `renderMenuItem()` treats a missing `image` as "this item has no thumbnail" and renders name/description/price full-width with no image area at all, rather than a placeholder square.
- `description`: `{ en, fi }`. Cocktail modifiers ("With Mezcal: +2€") and the Amazing Bowl's choose-your-sides/filling text are folded into this as plain prose, not separate interactive fields — nothing on the menu beyond the existing category tabs is clickable.
- A group can carry a standing note above its items via `data/i18n/*.json`'s `menu.notes.<groupId>` (used for Lunch's price/schedule line and Cocktails' "ask about Tequila & Mezcal" line).

## Signature dish carousel

`components/dishCarousel.js` replaced the old setup — a static 3-column grid on desktop, a manually-swipeable flex row on mobile — with one component that behaves identically at every screen size: a single row that auto-scrolls continuously and loops seamlessly, so a visitor sees every dish without tapping anything.

The loop trick: the dish list is rendered twice, back-to-back (`.dish-carousel-set`, `display: contents` so each set groups for `aria-hidden` on the duplicate without breaking the track's flex layout — the individual cards are still the track's direct flex children). A `requestAnimationFrame` loop advances a `translateX` offset and wraps it back to 0 once it passes the width of *one* set; since the second set is pixel-identical to the first, the wrap is invisible. A rAF loop (rather than a CSS `@keyframes` animation) is what makes the optional prev/next arrows possible without a fight: they just nudge the same `offset` value the auto-scroll already owns, so a manual click and the ongoing auto-scroll can never desync. `prefers-reduced-motion: reduce` simply skips starting the loop — the row sits still, and the arrows are still a fully working way to browse it.

Pausing: `pointerenter`/`pointerleave` cover hover on desktop, `pointerdown`/`pointerup` cover a touch press-and-release on mobile — the row pauses whenever either is active and resumes on release. The individual cards drop the `.reveal` scroll-fade-in class they'd normally carry (`renderDishCard()`'s own class is stripped after the fact) — a continuously horizontally-translating element under a scroll-linked reveal animation invited flicker for no real benefit, since these cards don't "enter" the page one at a time the way a vertical list does.

Because `renderSignatureDishes()` calls `renderDishCarousel()` again on every language switch (replacing `#dish-grid`'s contents wholesale), the rAF loop and its `resize` listener both self-terminate the moment their own `track` element is no longer in the document (`if (!document.body.contains(track)) return`) — otherwise every language toggle would leave one more orphaned loop running in the background forever.

## Asymmetric layout, soft-edged photos, and full-bleed imagery

Every section used to center its content in one narrow column — part of why the page felt empty on the sides on wide screens. The Story section (the only one that genuinely pairs a block of text with a single supporting photo — Find Us has a map instead, and the dish carousel/full menu/gallery are inherently symmetric grids/rows, so none of those were forced into this) is now a two-column layout on desktop: text on the left, photo on the right, both vertically centered (`.story-layout`, `flex-direction: row` above 900px). Below 900px it's the same DOM order stacked in a column instead (text, then photo) — no order-reversal trick needed, since "text first" is exactly what both layouts already want. Paragraph/heading text keeps its existing, readable max-width (`.story-body`'s 560px on desktop) rather than stretching edge to edge; asymmetric means text and image occupy different halves, not that text goes full-width.

The photo itself is soft-edged rather than a hard rectangle crop — `.story-photo-img` gets a `mask-image: radial-gradient(ellipse 72% 72% at 50% 50%, black 55%, transparent 100%)` (with the `-webkit-` prefix alongside), fading all four sides into the section's own background instead of a visible boundary line. An ellipse (not a circle) so the fade matches the photo's own 4:5 proportions. There's no dedicated Story photo yet — it reuses one of the `images/dishes/` shots as filler, the same way the gallery already does (see "Known gaps").

Sections without real photography yet (Menu, Visit) get `.section-ambient` instead of a flat background color — the same radial-accent-glow-over-`var(--bg)` technique `.hero` already uses, reused rather than invented fresh. It's isolated in its own class, applied directly on the `<section>` in `index.html`, so dropping it later (once those sections have real photos) is a one-line removal that touches nothing else.

`.container`'s `max-width: 1180px` still caps text exactly as before — that didn't change. What changed is imagery: the dish carousel and the gallery scrapbook now sit inside a `.full-bleed` wrapper (`width: 100vw; margin-left/right: calc(50% - 50vw)`, the classic break-out-of-parent-padding trick — robust across breakpoints without tracking each one's padding value; `body`'s existing `overflow-x: hidden` absorbs the sub-pixel rounding it can introduce) so both run closer to the viewport edges on wide screens instead of being boxed in by the section's own 56px side padding.

## Social links

`data/site.json`'s `social` object (`instagram`/`facebook`/`tiktok`, clean profile URLs — no tracking query params) is rendered in the footer by `footer.js` as a row of icon links (`.footer-social`) under the tagline, all `target="_blank" rel="noopener noreferrer"`. The icons are hand-drawn inline SVGs matching the site's own stroke-icon language (the theme toggle's sun/moon, the FAB's calendar) rather than imported brand assets — same reasoning as the custom CSS map pin instead of a raster logo. This is a new addition, not a rewire: `site.json` already had a (partial, and stale) `social` object, but nothing in the UI had ever rendered it before now.

## File structure

- `index.html` — page skeleton and section order
- `style.css` — all visual styling
- `script.js` — loads data, calls each component, wires up interactions
- `components/` — one reusable "template" per repeating piece (dish card, the dish carousel that stamps them out, menu row, gallery tile, button) plus one-off pieces (nav, mobile nav overlay, footer, language switcher, theme toggle, the special-event modal, the FAB, the Visit-section map)
- `data/menu.json` — dishes and full menu content
- `data/site.json` — address, hours, reservation link, socials
- `data/i18n/` — `en.json` / `fi.json`, one matching set of UI-chrome translation keys each
- `images/` — photos, organized by section (`hero/`, `dishes/`, `logo/`). The gallery has no photos of its own yet, so `galleryTile.js` also points at `images/dishes/` (see "Known gaps") — there's no separate `gallery/` folder to keep in sync.

## Status

Working prototype with the real menu (lunch, à la carte, drinks — see below), a scattered-photo gallery, an asymmetric two-column Story section with a soft-edged photo (see below), a continuously auto-scrolling signature-dish carousel (same component at every screen size — see below), scroll-spy nav highlighting, dish thumbnails in the full menu list (text-only rows for items with no real photo — see below), an EN/FI language switcher, a dark/light theme toggle, an auto-hiding mobile topbar with a hamburger-triggered full-screen section nav, an interactive map in the Visit section (see below), footer social links (see below), and a "Special Events or Inquiry" modal (see below), reachable both from the Visit section and a persistent floating action button. Scroll-reveal and tilt-hover are CSS-only and already active.

## Special events or inquiry

The "Special Events or Inquiry" action opens a modal (`components/eventModal.js`) with a plain form — event type, preferred date, guest count, details. It's reachable two ways: the primary (filled) button in the Visit section, listed ahead of the now-secondary (ghost) "Reserve a Table" button, and a persistent floating action button (`components/fab.js`) fixed to the bottom-right corner of every section. Both triggers call the same exported `openEventModal()` — there's only ever one modal instance in the DOM, not two.

Event type is a `<select>` (Birthday / Private Party / Corporate Event / Anniversary / Other) rather than free text, since a dropdown covers the realistic cases with less typing; selecting "Other" reveals a small text input for the visitor to specify, which is only included in the mailto body when Other is actually chosen (`Event type: Other — [their text]`; otherwise just `Event type: <selected>`). On submit the form builds a `mailto:` link from the field values (no backend, no network call) and hands off to the visitor's own email client via `window.location.href`, then closes. A plain-text fallback line under the Visit-section buttons spells out the email address directly, in case the visitor's device has no mail client configured and the mailto link does nothing visible.

The FAB sits at `bottom: 24px; right: 24px` (`z-index: 90`, below the modal's 100 but above ordinary content) — independent of the top-anchored `.shortcut-nav`/`.utility-bar`/`.mobile-topbar`, so the two never compete for space. Below 720px it drops its text label and becomes a plain 52px circular icon button, matching the site's tactile "3D" button shadow language at any size.

## Map

The Visit section's map (`components/map.js`) is [Leaflet](https://leafletjs.com/) loaded from a CDN, with plain OpenStreetMap tiles. It's centered on `data/site.json`'s `coordinates` field ({ lat: 60.1903, lng: 24.9535 }, geocoded for Aleksis Kiven katu 17), at zoom 16 — close enough to read the street. Scroll-wheel zoom is off by default so the map doesn't hijack an ordinary page scroll when the visitor's cursor happens to pass over it; drag-pan, the +/- controls, and pinch/double-click zoom all still work.

OSM only ships one (light) tile style — CartoDB's free Dark Matter/Positron tiles (used originally) now require a registered API key on a live domain, which showed up as a watermarked "API key required" tile instead of a map. The dark theme is simulated instead with a CSS filter (`invert(90%) hue-rotate(180deg)`) applied to `.leaflet-tile-pane` specifically — not `.map-card` as a whole — reset to `none` under `:root[data-theme="light"]`. Since Leaflet keeps tiles, markers, and popups in separate panes, scoping the filter to the tile pane means it never touches the marker or popup: the pin keeps matching `var(--accent)` exactly in both themes instead of also getting inverted. This is pure CSS keyed off the same `data-theme` attribute every other theme-aware part of the site already uses — no JS-side theme switching needed for the map at all.

The pin is a plain `L.divIcon` (a styled `<div>`, not a raster pin image) — `.map-marker` in `style.css` builds a classic pin silhouette (circle + triangular tip) purely from `var(--accent)`, so it follows the palette exactly like every button/price/heading elsewhere. Leaflet's own chrome (the popup, the attribution line — kept visible, small, in the map's corner, since OSM's usage terms require it) is re-themed the same way, off `var(--surface)`/`var(--ink)`. The map card itself reuses `.visual`'s exact treatment (`border-radius: 22px`, `overflow: hidden`, `box-shadow: var(--card-shadow)`) — the same look as the dish/gallery tiles.

"Get Directions" (`#visit-directions`, styled `.btn-ghost`) sits directly under the map card and opens `https://www.google.com/maps/dir/?api=1&destination=<site.address>` in a new tab — the universal Google Maps link format, which works cross-platform (including handing off to Apple Maps on iOS via Google's own redirect) without any separate device-detection logic.

Section order is heading → the two CTA buttons → the "Or email us directly at…" fallback line (small gap, reads as one cluster with the buttons) → a larger gap → the map card → Get Directions (small gap, reads as the map's own action).

Leaflet loads from a CDN classic `<script>` ahead of the deferred module `script.js`, so its `renderMap()` call sees a ready global `L`. That call is wrapped in a `try`/`catch` in `script.js`: an ad blocker, privacy extension, or a transient CDN hiccup leaving `L` undefined costs the page a map, not the rest of `init()` (footer, menu tabs, gallery, translations all still run regardless).

## Menu row layout

`components/menuItem.js` stacks every row the same way regardless of category: name (free to wrap to multiple lines), then description, then price, one under the other — never sharing a line with the name. That's what makes wine's four-column price grid (and any other long name) line up cleanly instead of fighting for horizontal space or ending up vertically off-center against wrapped text. Only items with a real `image` in `data/menu.json` get a thumbnail; everything else renders text-only, full-width, with no placeholder box.

## Image loading & size

Photos on a mobile connection were slow to appear, and several never showed up at all — visible as tiles stuck on the dark `#221512` fallback color from `.visual`'s `background-color`. Two compounding causes, both fixed:

- **Every dish photo was being downloaded twice.** The gallery had its own `images/gallery/` folder that was a byte-identical copy of `images/dishes/` (used as filler until real interior/atmosphere photos exist — see "Known gaps"). Since browsers cache by URL, `images/dishes/tuna-poke.jpg` and `images/gallery/tuna-poke.jpg` were two separate downloads of the same bytes. Deleted `images/gallery/` entirely; `galleryTile.js` now points straight at `images/dishes/`.
- **The photos themselves were oversized originals** — one was 2576×1449 (757KB) for what only ever displays at a few hundred pixels wide at most. Resized every file in `images/dishes/` to a 1000px long edge and re-encoded at quality 78, which also strips the bulky EXIF data these happened to carry. Combined with removing the duplicate folder, total image weight for a full page visit dropped from roughly 3.3MB to under 500KB.
- **Dish cards and gallery tiles used a CSS `background-image`** instead of a real `<img>`. Background-images have no equivalent to `loading="lazy"`/`decoding="async"`, and browsers are inconsistent about deferring them for off-screen elements — on a page with a dozen-plus photo tiles, several were still sitting empty well after the ones above the fold had already loaded. Both components now render an actual `<img loading="lazy" decoding="async">` layered under the existing scrim/caption overlay (same visual result, `.visual-img { position: absolute; inset: 0; object-fit: cover; }` in `style.css`), matching what `menuItem.js`'s thumbnails already did correctly.

New dish photos should go in at a similar size (long edge around 1000–1200px is plenty for how large these ever render) rather than an unedited original straight off a phone.

## Mobile navigation

Below 900px, the desktop pill nav (`#shortcut-nav`) is hidden and has nothing standing in for it except the hamburger button in the mobile topbar (`components/mobileNav.js`). Tapping it opens a full-screen overlay — a "Klande·stina" wordmark (the same accent-dot treatment as the footer logo), then Home / Story / Menu / Gallery / Find Us with thin accent dividers between them.

Visually it's built entirely from the site's own tokens rather than a fixed color, so it re-themes for free: the background is the same radial-accent-glow-over-`var(--bg)` treatment as `.hero`, and each link reuses `nav.js`'s pill-fill hover/tap pattern — a solid accent shape growing in behind the text (label and pill-fill are separate sibling spans, same split `nav.js` uses, so `applyTranslations()` re-setting the label's text never wipes the pill-fill out). The close button matches the site's raised-shadow/press-on-tap button language instead of a plain outlined circle.

The panel slides down from the top on open and back up on close (a container-level transform only — deliberately not an opacity fade, which briefly let the page behind it show through since the backdrop's own gradient would turn translucent too), while the wordmark and each link fade/rise in with a ~50ms stagger. Links call `preventDefault()` and drive the scroll themselves (`element.scrollIntoView()`) after the close animation actually finishes, rather than the previous approach of relying on the native anchor jump + site-wide `scroll-behavior: smooth` — needed so the overlay visibly closes before the page underneath jumps, instead of both happening at once. Scoped to `<=900px` only — both a `@media (min-width: 901px)` CSS guard and the fact that the toggle only exists inside the (itself hidden-above-900px) mobile topbar keep desktop nav behavior untouched.

Landing on a section used to leave a large, inconsistent gap under the fixed topbar (worst on Menu, since its tab row made the empty space obvious) — two compounding causes, both mobile-only fixes in the same `@media (max-width: 900px)` block in `style.css`: every `section` was still using desktop's 130px top padding, and none of the five nav targets (`#hero`/`#story`/`#menu`/`#gallery`/`#visit`) had a `scroll-margin-top` accounting for the topbar's height, so the browser scrolled each one flush to the very top of the viewport, right underneath (or behind) it. Mobile `section` padding is now `64px 24px`; the five targets get `scroll-margin-top: 85px` (the topbar's measured 69px height plus 16px of breathing room), landing each one with the same small, intentional gap instead.

That fix on its own wasn't enough, though: `initMobileTopbarAutoHide` (a plain scroll listener — hide on scroll down, show on scroll up) can't tell a nav-triggered jump apart from the visitor scrolling by hand, so it was hiding the topbar mid-jump — right as the visitor landed, with nothing left to justify the `scroll-margin-top` clearance reserved for it. A link click now sets `document.body.dataset.navJump = "true"` for the duration of its own `scrollIntoView()` call (cleared on the `scrollend` event, with a 1s timeout fallback for browsers without it) and force-shows the topbar first; the scroll handler skips its hide logic entirely while that flag is set. A second, unrelated bug reported alongside this: opening the site fresh sometimes landed mid-page instead of at the top — iOS Safari in particular can restore a tab's last scroll offset on a fresh visit to the same URL rather than starting at 0. `index.html`'s inline `<head>` script now sets `history.scrollRestoration = "manual"` to opt out of that; it has no effect on an intentional `#section` link, which is a separate browser mechanism.

## Editing translations

UI chrome (nav, hero, section headings, story/visit copy, footer, the event modal) lives in `data/i18n/en.json`, `fi.json` — same keys in each file. Menu item `description` fields in `data/menu.json` are `{ "en": ..., "fi": ... }` objects; dish/item *names* stay untranslated on purpose (they're already Spanish). `script.js` resolves everything by the active language at render time. (Spanish was dropped as a site language — the site only needs EN/FI now — though dish/item names being Spanish already is unrelated to that and hasn't changed.)

## Theme

Dark is the default palette. Light theme's CSS variables live in the `:root[data-theme="light"]` block in `style.css`. `script.js` sets the visitor's initial theme from `prefers-color-scheme` (via a small inline script in `index.html`'s `<head>`, so there's no flash of the wrong theme), then remembers a manual toggle in `localStorage`.

Known gaps:
- **Map tiles use plain OpenStreetMap tiles, with the dark theme simulated via an `invert()`/`hue-rotate()` CSS filter** (CartoDB's free dark/light tiles, used originally, now require a registered API key on a live domain) — map tiles can't follow CSS variables the way the rest of the site's colors do. Only the pin and card chrome are palette-driven. If the final brand palette calls for a proper tinted map instead of a simulated dark one, that would be a separate follow-up (e.g. tuning the filter further, or a different tile provider that offers a real dark style with a free tier).
- The `gallery` array in `data/menu.json` currently reuses the dish photos from `images/dishes/` as filler (`galleryTile.js` points straight at that folder — there's deliberately no separate `images/gallery/` copy of the same files, see "Image loading & size" below) — real interior/atmosphere photos are still needed.
- **FI translations are AI-generated** (by Claude) and should be reviewed by a native speaker before real launch — both for accuracy and for tone.
- **The G/M/L allergen legend needs confirming with the owner** (see "Editing the menu" above) — codes are stored exactly as printed, meaning is not asserted.
- **Two menu items have an item-level gap from illegible/uncertain source photos, flagged rather than guessed:**
  - Lunch's "Sea Bass in Mango Salsa" had an allergen code in parentheses that's obscured by glare in the photo — stored with an empty `allergens` array; worth re-checking against the physical menu.
  - Wine's "House Sparkling Wine" — read as `12cl €10 / 16cl — / 24cl — / bottle €36` (only one glass size offered), but that part of the photo also has glare across it — worth double-checking that reading against the physical menu or POS.
- Menu **thumbnails use 12px rounded squares**, not circles, to stay consistent with the rounded-square treatment already used everywhere else images appear (dish cards, gallery tiles). Only a handful of items have real photos (the ones that already had dish photography); the rest — most of tacos, all of chilaquiles/desserts/drinks/wine — render as text-only rows with no thumbnail at all (see "Menu row layout" above) rather than a placeholder box, since a blank tinted square read as a broken image more than an intentional design choice.
- **Story section copy was rewritten from the owner's own "About Klandestina" text** (photographed board), replacing the previous entirely-invented placeholder copy (including a fabricated "— Andrés, chef & owner" quote attribution, which has been removed — the real source has no attributed name). Kept the pull-quote box treatment; the section is now a two-column layout with a photo (see "Asymmetric layout, soft-edged photos, and full-bleed imagery" above) — that photo is filler reused from `images/dishes/`, the same as the gallery, since there's no dedicated Story/interior photo yet. Two things from the source text are flagged rather than guessed at:
  - **"Harju Kallio"** is used verbatim as printed — I can't independently confirm whether this is meant as one place name, a reference to "Harjutori" (a square in Helsinki's Kallio district), or something else.
  - **"two and a half years"** is a relative duration with no anchor date on the source material — used verbatim to match the real text, but as permanent website copy it will silently become inaccurate as time passes. Worth deciding whether to replace it with an absolute year/date range, or accept it needs periodic manual updating.
- Several previously-hardcoded colors (muted text opacities, button/tab "3D" shadow tones, the floating nav's glass background) were converted to theme-aware `color-mix()`/CSS-variable expressions so they'd read correctly in both themes; a few — the dark gradient scrim behind photo captions, and the caption text sitting on top of it — were deliberately left theme-independent, since they overlay photographs rather than the page background and need to stay legible regardless of site theme.
- `favicon.ico` is referenced in `index.html` but still doesn't exist in the repo (pre-existing gap, unrelated to this pass) — the browser tab will show a generic icon until one is added.
- **Dish card width settled on 240px empirically** (tested across viewport widths from 390px to 1920px, the smallest size with no caption overflow against the fixed 3:4 image aspect ratio) — originally as a grid-column floor, now as the fixed flex-basis every carousel card uses at every breakpoint (see "Signature dish carousel" above, which replaced the old desktop-grid/mobile-flex split this note originally described). Also added `flex-wrap: wrap` to `.dish-top` (name/price row) — at this card width, a long price could otherwise overlap the wrapped dish name instead of dropping to its own line.
- **Mobile topbar (<=900px).** A fixed bar (reusing `.shortcut-nav`'s glass/blur styling) replaces the desktop's separate `#brand-mark` + `.utility-bar` on small screens, holding the wordmark, language switch, and theme toggle in one row. It auto-hides on scroll down and reappears on scroll up (`script.js`, `initMobileTopbarAutoHide`, 8px threshold to avoid jitter). Implementation note: the language switch and theme toggle are genuinely rendered twice (`#lang-switch`/`#theme-toggle` for desktop, `#mobile-lang-switch`/`#mobile-theme-toggle` for the topbar) rather than one instance being moved around — simpler and more robust than reparenting fixed-position elements across a breakpoint. They stay in sync automatically: the theme icon swap is pure CSS keyed off `<html data-theme>`, and `setLanguage()` updates both lang-switch instances' active state on every change.
- **Gallery is now a scattered "scrapbook"** (`display: flex; flex-wrap: wrap`, not `grid`) — six rotation/offset variants cycling by `nth-child`, negative horizontal margins for overlap, hover straightens the tile and lifts it with its own shadow (overrides the site-wide 3D tilt-hover via higher CSS specificity, since that effect would otherwise fight the tile's own base rotation instead of countering it back toward flat). Still uses the existing dish photos as filler.
- **"Find Us" section is now CTA-only** — heading + Reserve button. Address/hours/contact live in the footer alone now; removed the now-unused `visit.addressLabel`/`hoursLabel`/`contactLabel` i18n keys and `.visit-grid`/`.visit-col` CSS along with it.
